# Build SignalCraft AI — Personal AI Content Intelligence & Agent Platform

You are a senior full-stack AI engineer, backend architect, data engineer, and product engineer.

Build a production-quality MVP called **SignalCraft AI**.

## 1. Product Vision

SignalCraft AI is not a basic AI content writer.

It is a **personal AI content intelligence and generation platform** that:

1. Understands an individual creator.
2. Understands their niche, audience, goals, expertise, and writing style.
3. Collects fresh information from the web and other data sources.
4. Detects current trends and content opportunities.
5. Determines which trends are relevant to that specific user.
6. Recommends what the user should create.
7. Generates platform-specific content.
8. Critiques and improves generated content.
9. Stores the user's content history.
10. Analyzes content performance.
11. Learns what works for the individual creator.
12. Uses that knowledge to improve future recommendations.

The core product loop is:

USER → RESEARCH → TREND INTELLIGENCE → CONTENT OPPORTUNITY → AGENT → CONTENT → PERFORMANCE → LEARNING → BETTER RECOMMENDATIONS

The product should feel like a **personal AI content strategist**, not an LLM wrapper.

# 32. Error Handling

Never silently fail.

If research fails:

Show a useful message.

If the LLM fails:

Allow retry/fallback.

If structured output is invalid:

Validate and retry within a limited number of attempts.

If an external source is unavailable:

Continue with available sources and clearly mark limitations.

Never fabricate research or citations.

Never claim a topic is trending without data supporting the claim.

---

# 33. Source Grounding

Whenever content is based on current research:

Store source references.

Content generation should receive relevant evidence.

Do not allow the model to invent URLs, statistics, quotes, or current events.

For research-backed content, maintain:

source
title
URL
date
summary

The UI should make research provenance visible where appropriate.

# 34. Cost Optimization

Optimize LLM usage.

Use cheap/small models for:

* Classification
* Tagging
* Simple summarization
* Extraction

Use stronger models for:

* Strategy
* Complex reasoning
* Final content
* Criticism

Cache repeated research.

Do not send huge histories to every LLM call.

Retrieve only relevant memory.

Use embeddings for semantic retrieval.

Track estimated LLM cost.
